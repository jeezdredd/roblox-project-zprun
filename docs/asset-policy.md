# Asset policy — animation and audio

Permanent rules for every stage of this project, not a one-off task. Referenced from `CLAUDE.md`.

## Why this exists

Code is good at *dynamics* — springs, phases, impulses, procedural layers. Code is bad at *authored keyframes* and *timbre*. Every attempt to generate artistic animation or synthesise audio in this project produced work that had to be thrown away. The split below is the fix.

## Hard rules

1. **Authored poses are allowed for the viewmodel and zombies, under one condition: every pose is verified by screenshot before it counts as done.** The original ban existed because code could not see its own output. Studio MCP `screen_capture` closes that loop, so the ban is lifted for these two rigs. A pose that looks broken gets reworked, never shipped as-is. Everything else still comes from external clips: player body gaits, cinematic gestures, and anything on the R15 character outside the zombie set.
2. **Never synthesise audio.** No tone generation, no noise shaping, no assembling a sound from primitives — in code or in tooling. Every audio slot is a real file from the whitelist, registered in `assets/manifest.json`.
3. **Silence beats a bad placeholder.** No suitable file → leave the slot at `assetId = 0` (systems already guard on `> 0` and stay silent) and add a line to `assets/NEEDED.md`. Never plug a hole with a sound from an unrelated category, and never reuse one file across unrelated events.
4. **Never invent an assetId.** Ids come only from a real upload through the manifest pipeline, or from the Creator Store after the owner has inserted the asset and provided the id.
5. **Licensing.** Whitelist sources only. **Unreal (Fab) and Unity Asset Store packs are forbidden even when free** — their licences are engine-bound. Every new asset gets a manifest entry with a source URL and a licence, and `assets/LICENSES.md` is regenerated by `scripts/sync_configs.py`.

## Whitelist

### Animation

| Slot group | Source | Handling |
| --- | --- | --- |
| Viewmodel placeholders (idle, fire, reload, inspect, raise) | Universal Viewmodel Template (Roblox DevForum free release, no attribution required) | Owner inserts it in Studio; see *Rig compatibility* |
| Zombies (idle ×3, shamble, sprint, attack, feeding) | Mixamo — free, licence permits use in games | Blender retarget pipeline; owner downloads the clips |
| Player body (run with weapon, strafes, stumble, death) | Mixamo | Same pipeline |
| Cinematic (pilot, copilot, seated squad) | Mixamo (sitting / shooting / transform poses) plus procedural camera | Bodies are clips, camera and timing are code |
| Ready-made free Roblox rigs and kits | Creator Store, free filter | Only after the owner approves a specific asset |

### Audio

Creator Store licensed library (id available immediately), Sonniss GameAudioGDC (royalty-free), Freesound with the CC0 filter, OpenGameArt (CC0 or CC-BY with attribution recorded in `LICENSES.md`), Kenney (CC0).

## Rig compatibility

Roblox animation binds by joint name, so:

1. The owner inserts the Universal Viewmodel Template in Studio and exports its structure (Motor6D names and hierarchy). **Ask for that dump before starting the Motor6D conversion** — do not guess names.
2. Our viewmodel Motor6D tree is renamed to match the template, or a joint mapping table is written if a name collides with our own logic. Template clips then play on our rig through an `Animator`, and procedural offsets land on top through `Motor6D.Transform` written in `RunService.Stepped`.
3. Zombies and the player body stay on the standard R15 rig. Mixamo clips retarget onto R15; no custom skeletons without a stated reason.

## Blender pipeline

See `tools/animation_pipeline/README.md` for the owner-facing steps and `tools/animation_pipeline/retarget_mixamo.py` for the headless Blender script.

Once clips are uploaded, the owner records the ids in the manifest under the `animation` type, `scripts/sync_configs.py` regenerates `src/shared/config/AssetIds.luau`, and every `Animator:LoadAnimation` call reads its id from there — never from a literal.

## Quality checklist

Run this before shipping any feature that involves animation or audio.

**Animation**
- No bone teleports between frames; state transitions blend by weight with `FadeTime >= 0.15`.
- Loop clips have no visible seam (first and last frame agree).
- The procedural layer does not fight the clip: `Transform` is written in `Stepped`, after the Animator pass.
- Event audio is driven by `KeyframeMarker` in the clip, not by a wall-clock timer.

**Audio**
- Minimum variation count met — footsteps, gunshots and bites need at least 3, otherwise the slot goes to `NEEDED.md`.
- Volumes are levelled within a class; nothing sticks out by roughly 10 dB.
- RollOff matches the event scale (a whisper is not an explosion); 3D sounds do not carry across the whole map.
- Nothing is synthesised; every file is in the manifest with a licence.

## Division of labour

**Claude Code:** slots, configs, pipeline scripts, integrating clips and sounds by id, procedural dynamics, maintaining `NEEDED.md`, writing instructions for the owner.

**Owner:** downloads files per `NEEDED.md`, runs the Blender scripts, uploads through the manifest script, inserts Creator Store assets, approves quality by eye and ear in Studio.

If generating an animation or a sound starts to look like the quick option — that is the trap this document exists to prevent. Create the slot and write the line in `NEEDED.md` instead.
