# Внедрение находок из разбора Into the Dead 2

Инструкции для работы над Task Force Z. Основаны на `docs/research/ITD2-teardown.md`
и на текущем состоянии кодовой базы (проверено по `src/` на 30.08.2026).

Переносятся **решения и структуры**, не код и не ассеты PikPok.

Порядок задач — по убыванию отдачи. Каждая самостоятельна, можно брать по одной.
После каждой: `selene src/`, `python3 tools/validate_api.py`, `rojo build`.

---

## 1. Секции спавна с рампой Start → End по кривой

**Отдача: высокая. Это главное отличие их системы от нашей.**

### Что сейчас

`ZombieAI.spawnForChunk(chunkIndex, chunkPivot, chunkLength, count)` в
`src/server/systems/ZombieAI.luau:370` раскидывает `count` зомби равномерным
рандомом по прямоугольнику чанка. Плотность приходит одним скаляром
`obstacleDensity` из `DifficultyConfig`. Внутри чанка ничего не меняется.

### Что сделать

Ввести понятие **секции спавна**: отрезок трассы, на протяжении которого каждый
параметр интерполируется от стартового значения к конечному по кривой.

Новый файл `src/shared/config/ZombieSpawnConfig.luau` — data-only, по конвенции проекта:

```lua
--!strict

export type Ramp = {
	start: number,
	finish: number,      -- nil-эквивалент: держать start (у них это сентинел -1)
	curve: string,       -- ключ в EASINGS ниже
}

export type SpawnSection = {
	id: string,
	difficultyTier: number,   -- 0..5
	densityTier: number,      -- 1..5
	zombieIds: { string },    -- какие типы разрешены в этой секции

	spawnDelayMin: Ramp,
	spawnDelayMax: Ramp,
	lateralDistanceMin: Ramp,
	lateralDistanceMax: Ramp,
	leftSideChance: Ramp,

	clumpChance: Ramp,
	clumpRadius: Ramp,
	clumpSizeMin: Ramp,
	clumpSizeMax: Ramp,

	lyingDownChance: Ramp,
	alertChance: Ramp,
}
```

Кривые держать простыми именованными функциями (`linear`, `easeIn`, `easeOut`,
`hold`) — полноценный `AnimationCurve` в Luau не нужен, у них в данных
подавляющее большинство кривых линейные либо плоские.

Хелпер `ZombieSpawnConfig.evaluate(ramp, t)` где `t` — прогресс по секции 0..1.

`ZombieAI.spawnForChunk` заменить на спавн по таймеру, а не пачкой: держать
аккумулятор до следующего спавна, каждый тик брать `spawnDelayMin/Max` в текущей
точке секции и ставить следующий спавн. Это то, что делает их `ZombieManager`
через `m_spawnNextZombieTimer`.

### Ориентиры по числам

Из 1365 их секций (`docs/research/ITD2_spawn_sections.json`):

| Параметр | Диапазон в шиппящейся игре |
| --- | --- |
| Задержка спавна | 0.05 – 6 с |
| Радиус кучи | 0.1 – 12 |
| Размер кучи | 1–12 (min), 2–15 (max) |
| Полуширина полосы | 0 – 16 |

Их единицы — метры Unity, наши — стады Roblox (`LANE_WIDTH = 240`), пересчитывать
пропорционально, а не один к одному. Полезно соотношение: их полоса ±6.5 при
скорости бега 6.0 — то есть игрок пересекает полосу примерно за 2 секунды.
У нас `LANE_WIDTH = 240` при `BASE_RUN_SPEED = 24` — полоса пересекается за 10 секунд.
Полоса заметно шире относительно скорости; стоит либо сузить, либо поднять
боковую скорость, иначе уклонение ощущается вяло.

### Кучность

Отдельная механика, которой у нас нет совсем: с вероятностью `clumpChance`
вместо одного зомби спавнится группа из `clumpSizeMin..Max` в радиусе `clumpRadius`.
У них в плотных секциях `clumpChance = 1.0`, радиус 8, размер 7–9.
Плюс `spawnBarrelWithClumpChance` (у них 10 %) — взрывная бочка вместе с кучей,
то есть куча сразу читается как возможность, а не только как угроза.

## 2. Пересмотреть разгон скорости

**Отдача: высокая. Затрагивает базовое ощущение забега.**

### Что сейчас

`GameConstants.luau`:
```
BASE_RUN_SPEED = 24
MAX_RUN_SPEED = 60
SPEED_GAIN_PER_STUD = 0.002
```
Скорость непрерывно растёт с дистанцией, потолок в 2.5 раза выше старта.

### Что показал разбор

Из 637 уровней Into the Dead 2 **619 держат постоянную скорость 6.0**.
Разгон включён у единиц (7 → 9 за 130 секунд). Сложность растут плотностью
и составом зомби, не скоростью игрока.

Причина, судя по устройству их системы: постоянная скорость даёт игроку выучить
тайминги уклонения. Когда растёт и скорость, и плотность, навык не переносится
между отрезками забега, и смерть читается как несправедливая.

### Что сделать

Не выпиливать разгон, а сделать его параметром локации, как у них — уровневым,
а не глобальным. В `LocationsConfig` добавить необязательные поля:

```lua
runSpeedInitial: number?,
runSpeedMax: number?,
runSpeedRampTime: number?,   -- секунды, не стады
```

Отсутствуют — держать постоянную `BASE_RUN_SPEED`. Заметь: у них рампа по **времени**,
а у нас по дистанции (`SPEED_GAIN_PER_STUD`). Время предсказуемее: дистанция сама
зависит от скорости, получается положительная обратная связь.

Затем прогнать плейтест с постоянной скоростью 24 и растущей плотностью — сравнить
ощущение с текущим. Это решение о геймдизайне, данные только показывают, что
флагман жанра выбрал иначе, чем мы.

## 3. Три радиуса реакции вместо бинарного агро

**Отдача: средняя. Дёшево внедряется.**

### Что сейчас

`DifficultyConfig` даёт один `aggroDistance` (у Easy `math.huge`, у Hard `0`),
`ZombiesConfig` — один `reactionDelay`. Зомби либо спит, либо гонится.

### Что сделать

В `ZombiesConfig.ZombieConfig` добавить три радиуса по их модели:

```lua
awareRadius: number,    -- заметил, поворачивает голову, меняет idle-анимацию
alertRadius: number,    -- поднялся, развернулся, начал движение
attackRadius: number,   -- бьёт
```

Плюс `turnToFacePlayerChance: number` — не все разворачиваются, часть остаётся
безучастной. Это дешёвый способ сделать толпу неоднородной.

В `ZombieAI` состояние зомби становится перечислением (`Idle` / `Aware` / `Alert` / `Attack`)
вместо булева `moving`. Переходы завязать на радиусы, а `ZombieAnimator` — на состояние.

Отдельно: у них раздельные наборы параметров движения для спокойного и
поднятого состояния (`m_movementDefintion` / `m_alertMovementDefintion`) —
включая `zombieSpeedWhenShotMultiplier`, ускорение от попадания. У нас один `walkSpeed`.

## 4. Скользящее столкновение вместо бинарной смерти

**Отдача: средняя. Убирает главную причину ощущения несправедливости.**

### Что сейчас

`ZombieAI.luau:91` — касание сразу снимает `touchDamage`. Задел зомби краем или
влетел в центр — разницы нет.

### Что сделать

Ввести два порога по боковому смещению, как у них
(`m_collisionMaxXDeathDistance` / `m_collisionMaxXGlanceDistance`):

```lua
collisionDeathDistance: number,   -- ближе — полный урон
collisionGlanceDistance: number,  -- между ними — скольжение
glancePower: number,              -- насколько разворачивает и тормозит
```

Внутри `glance`-зоны вместо урона: импульс в сторону от зомби, кратковременная
потеря боковой скорости, триггер `Stumble` (клип уже заведён в `AnimationsConfig`,
слот пустой). Игрок наказан, но жив — и понимает, что задел краем.

Это же даёт применение `PlayerMovement.m_stumbleMin/m_stumbleBoost` из их системы:
спотыкание не мгновенное, у него есть минимальная и усиленная величина.

## 5. Тиры сложности и плотности как именованные пресеты

**Отдача: средняя. Экономит время при наполнении контентом.**

У них секции названы `ZSS_Diff4_Dense4_Z1234_LargeClump_<уровень>` — тир сложности,
тир плотности, разрешённые типы зомби, пресет кучности. Уровень собирается
из готовых блоков, а не настраивается с нуля.

Распределение по 1365 секциям: сложность 0–5 (пик на 3), плотность 1–5 (пик на 3).

Завести в `ZombieSpawnConfig` таблицу пресетов и собирать секции из них:

```lua
ZombieSpawnConfig.difficultyTiers = { [1] = {...}, ... [5] = {...} }
ZombieSpawnConfig.densityTiers = { ... }
ZombieSpawnConfig.clumpPresets = { None = ..., Small = ..., Large = ... }
```

Локация в `LocationsConfig` тогда описывается списком секций по тирам, а не
россыпью чисел.

## 6. Анимации зомби — массивы вместо одного клипа

**Отдача: средняя. Требует ассетов.**

У них на каждое состояние массив клипов со случайным выбором: четыре тира движения
(walk / wog / jog / run), варианты под телосложение, отдельные наборы подъёма,
падения, спотыкания, смертей по типу урона, отбрасывания влево / по центру / вправо.

Нам столько не нужно, но текущая схема «один клип на слот» в `AnimationsConfig`
делает толпу заметно синхронной. Минимум: 2–3 варианта на `walk_shuffle` и `idle`,
выбор при спавне, плюс случайный сдвиг фазы (`AnimationTrack.TimePosition`) —
последнее вообще бесплатно и убирает синхронность уже сейчас, до появления клипов.

Изменить в `AnimationsConfig.ClipConfig` `assetId: number` на `assetIds: { number }`
и брать случайный при загрузке в `ZombieAnimator`.

## 7. Защита от застревания в стену

**Отдача: низкая сейчас, высокая после релиза.**

У них в `PlayerMovement` есть `m_flatWallCheckInterval`, `m_lastFlatWallCheckZ`,
`m_minZDistanceToNotBeStuck`, `m_disableFlatWallDeath` — периодическая проверка,
что игрок продвинулся по Z хотя бы на минимальное расстояние, иначе он застрял
в геометрии и это обрабатывается явно.

Такое обычно дописывают после багрепортов. Заложить сразу дешевле:
в серверном трекере дистанции проверять раз в N секунд, что Z вырос,
иначе — телепорт в свободную точку полосы или засчитанная смерть, по вкусу.

## 8. Мелочи, которые стоит забрать

- **Пул трупов.** У них `m_corpsePool` фиксированного размера — трупы переиспользуются.
  У нас `ZombieAI.clearChunk` уничтожает модели. При росте плотности это станет заметно.
- **Минимальная дистанция между зомби.** `m_minZombieSeparationSq` и
  `m_minKnockbackSeparation` — не дают толпе слипаться в одну точку.
- **Статические зомби.** Отдельная система декоративных зомби со своими дистанциями
  спавна и деспавна — дешёвое наполнение кадра без нагрузки на ИИ.
- **Событийный спавн.** `m_spawnEventSize` / `m_spawnEventInterval` — периодические
  всплески поверх базового потока.

## Чего не делать

Не переносить в проект модели, текстуры, анимационные клипы и звук Into the Dead 2.
Политика ассетов (`docs/asset-policy.md`) требует CC0 или собственных работ
с записью в `assets/LICENSES.md`. Извлечённые файлы — только для просмотра как референс.

Не копировать их имена классов и полей буквально: у нас свои конвенции
(`ZombiesConfig`, `ZombieAI`), и калька на `m_`-префиксах в Luau неуместна.
